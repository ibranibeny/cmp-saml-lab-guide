User lokal Keycloak hanya menjadi pembanding; lab ini tidak membuat user tersebut bisa masuk ke Azure.

1 · Enterprise App non-gallery (SAML)

Buat aplikasi “Create your own application” di Entra, pilih SAML. Isi Identifier (Entity ID) dan Reply URL (ACS) dengan nilai yang disalin dari Keycloak. Entra lalu menerbitkan sertifikat penandatangan dan App Federation Metadata URL.

2 · Attributes & Claims + JIT

Klaim default (given name, surname, email, name) dikirim di assertion. Keycloak memakai klaim ini untuk membuat user secara just-in-time. Poin penting: jika atribut sumber di Entra kosong, klaimnya tidak dikirim sama sekali.

3 · User uji, app role, assignment

Video memakai user uji dan meng-assign-nya ke aplikasi. App role yang di-assign ikut terkirim sebagai klaim role, sehingga bisa dipetakan ke role Keycloak.

4 · Keycloak 26: SAML v2.0 Identity Provider

Tambahkan IdP SAML v2.0, salin Redirect URI dan Service provider entity ID ke Entra, impor metadata Entra, lalu tambahkan IdP mappers. Aplikasi (Spring Boot di video) tetap memakai OIDC ke Keycloak.

Tiga trust relationship

Entra mempercayai SP

Entra hanya mengirim assertion ke Reply URL terdaftar untuk Identifier yang cocok, dan hanya untuk user yang di-assign. AuthnRequest lab tidak ditandatangani; produksi sebaiknya menandatanganinya.

Keycloak mempercayai Entra

Keycloak menerima assertion hanya jika tanda tangannya valid terhadap sertifikat signing Entra yang diimpor. Ini satu-satunya kunci kepercayaan; jaga rotasinya.

Aplikasi mempercayai Keycloak

claims-app tidak pernah melihat SAML. Ia hanya mempercayai ID token OIDC dari issuer http://localhost:8180/realms/saml-lab yang diverifikasi lewat JWKS.

Temuan L400 dari uji live

PENTING

  1. Klaim role terkirim tanpa claims-mapping policy

    Untuk user yang di-assign ke app role, Entra otomatis mengirim http://schemas.microsoft.com/ws/2008/06/identity/claims/role = CMP.Reader. Cukup satu mapper Keycloak SAML Attribute to Role.

  2. Atribut kosong = klaim hilang

    User uji tidak punya mail dan surname, sehingga klaim emailaddress dan surname tidak dikirim. Akibatnya Keycloak meminta Last name di first broker login, dan email diambil dari klaim name (UPN).

  3. Identitas stabil = object ID, bukan email

    Principal broker memakai klaim objectidentifier (immutable). UPN/email bisa berubah; object ID tidak. Username JIT di Keycloak menjadi GUID tersebut.

  4. Entra menandatangani Assertion, bukan Response

    Capture menunjukkan Response tidak bertanda tangan sedangkan Assertion bertanda tangan (RSA-SHA256, exclusive C14N). Karena itu Want Assertions signed harus On di Keycloak.

  5. Jendela waktu 65 menit

    Entra memundurkan NotBefore sekitar 5 menit dan memberi NotOnOrAfter sekitar 1 jam. Error expired hampir selalu berarti jam host/WSL bergeser.

  6. MFA terlihat di klaim, bukan di AuthnContext

    AuthnContextClassRef tetap Password, sedangkan klaim authnmethodsreferences berisi multipleauthn. Jika aplikasi perlu bukti MFA, petakan klaim ini; jangan mengandalkan AuthnContext.

  7. Egress container bisa diblokir

    Di laptop dengan Global Secure Access, DNS container mengembalikan alamat sintetis 6.6.x.x sehingga import metadata dari URL gagal. Solusi: upload file metadata dan pakai sertifikat statis, dengan konsekuensi rotasi sertifikat manual.
